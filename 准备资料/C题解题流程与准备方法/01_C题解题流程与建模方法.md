# 国赛 C 题解题流程与建模方法

> 适用对象：准备全国大学生数学建模竞赛、重点考虑近年来本科组 C 题的队伍。以本仓库 2019—2025 年 C 题原文为案例，规则核对日期为 **2026-09-08**。
>
> 本文是解题方法与训练建议，不是官方标准答案，不预测下一届题型，也不保证获奖。文中的简化模型、时间分配和验收指标均为备战建议；具体赛题、全国规则及所在赛区当年通知优先。

配套阅读：
- [建模手备战指南](./02_C题建模手备战指南.md)：重点解决“理论学什么、学到什么程度、如何设计模型”。
- [编程手备战指南](./03_C题编程手备战指南.md)：重点解决“工具学什么、如何实现、如何保证结果可复现”。

**阅读路线：** 先看第 1—3 节理解 C 题与拆题方法，再按第 4—9 节完成建模闭环，最后用第 10—13 节组织比赛和验收。

## 1. C 题到底在考什么

### 1.1 一句话理解

**把现实问题转化为可计算、可检验、可解释的数学问题，再把计算结果转回有依据的结论或可执行方案。**

近年来的本科 C 题经常包含数据处理、统计分析、预测、评价和优化，但这是一种备战上的归纳，不是官方对 C 题永久固定的分类。不能把 C 题简单理解为：

- “拿到 Excel，跑几个机器学习算法”；
- “第一问做相关性，第二问熵权 TOPSIS，第三问遗传算法”；
- “只要拟合精度高，其他部分不重要”；
- “C 题没有机理、不需要运筹优化”。

一个更有用的结构是：

```text
现实问题与业务规则
        ↓
对象、数据口径、待回答的问题
        ↓
描述 / 解释 / 预测 / 评价 / 决策
        ↓
假设 + 数学模型 + 求解算法
        ↓
结果检验 + 不确定性分析
        ↓
具体答案、可执行方案、论文与支撑材料
```

**模型不等于算法，算法不等于软件。**

例如，“预算和库存约束下最大化利润”是模型；“分支定界”是求解算法；“通过 Python 调用 MILP 求解器”是实现方式。“用了 Python”不能代替模型说明，“用了遗传算法”也不能代替目标函数和约束。

### 1.2 用真题认识能力范围

下表“题面核心任务”概括赛题要求；“训练方向”是本文建议，并非题目指定算法。[题源]

| 年份与题名 | 题面核心任务 | 推荐训练方向 | 容易忽略的问题 |
|---|---|---|---|
| 2019《机场的出租车问题》 | 司机选择、实际机场数据分析、上车组织、短途车优先安排 | 收益比较、排队分析、离散事件仿真、效率与公平的多目标决策 | 需要自行收集相关数据；到达过程未必满足简单平稳排队假设 |
| 2020《中小微企业的信贷决策》 | 量化信贷风险，确定信贷策略，并考虑突发因素 | 企业级特征、风险评价或分类、利率与流失关系、资金配置优化 | 作废票、负数票有业务含义；风险评分不自动等于违约概率 |
| 2021《生产企业原材料的订购与运输》 | 供应商重要性、未来 24 周订购与转运、产能提升 | 供货可靠性、产出当量、库存平衡、整数规划、情景分析 | 订货量不等于供货量；转运损耗率中的 0 表示没有运送 |
| 2022《古代玻璃制品的成分分析与鉴别》 | 风化关系、成分规律、风化前成分预测、分类与亚类、关联差异 | 列联分析、回归、分类、聚类、成分数据分析、敏感性分析 | 同一文物可有多个采样点；比例数据有总和约束，不能随意解释相关性 |
| 2023《蔬菜类商品的自动定价与补货决策》 | 销量规律与关系、品类补货定价、带单品数和陈列量约束的决策、补充数据建议 | 多表清洗、时间聚合、需求与价格建模、预测和优化衔接 | 销量不一定等于需求；定价与需求存在相互影响；损耗不能重复计费 |
| 2024《农作物的种植策略》 | 稳定参数下两类滞销处理、多年不确定性策略、替代互补与相关性分析 | 地块—作物—季节—年份建模、MILP、情景模拟、风险控制 | 土地适种、重茬、三年豆类、2023 初始状态；未来信息不能提前用于决策 |
| 2025《NIPT 的时点选择与胎儿的异常判定》 | 浓度关系与显著性、BMI 分组和检测时点、综合因素与误差、女胎异常判定 | 重复测量分析、达标时间建模、风险决策、分组验证、类别不平衡 | 同一孕妇多次采血/检测；未观察到达标不等于永不达标；出生后信息不能作为检测时预测特征 |

读早期资料时还要核对组别：不能把早年专科组 C 题与近年来本科组 C 题不加区分地混在一起统计“套路”。2019 年官方题目数量增至五道，当年的论文规范明确本科组从 A/B/C 中选题。[组别]

### 1.3 什么比“高级模型”更重要

官方章程列出的主要评奖标准包括：**假设的合理性、建模的创造性、结果的正确性和文字表述的清晰程度**。[规1]

因此，优先追求：

1. 每一问都被准确回答，而不是只做自己熟悉的部分。
2. 模型能表达题目要求，而不是删掉关键约束使问题变容易。
3. 数据处理与结论可追溯，没有泄漏、错单位和虚构结果。
4. 能说明模型为什么适用、什么时候失效。
5. 最终方案能执行，论文中的数字能由代码重现。

创新可以是更贴合业务的变量、合理的约束、正确的不确定性处理或更可信的验证，不必表现为创造一个新算法名称。

## 2. 总体策略：先完成基线，再围绕证据改进

推荐两轮推进。

### 第一轮：做出最小完整解答

对每一问，先做到：

- 有明确输入和输出；
- 有简洁且合理的假设；
- 有可以运行的模型；
- 有具体答案；
- 有至少一种基本检验。

例如：先用历史同期均值预测销量，先用可解释规则筛选供应商，先用确定性规划生成一个满足约束的方案。

这不意味着基线就是最后答案，而是先建立**比较对象和失败时可保留的方案**。

### 第二轮：只改进有证据表明重要的薄弱环节

改进顺序通常是：

```text
题意与数据错误
    > 约束遗漏和数据泄漏
    > 验证方式错误
    > 关键参数估计不可靠
    > 模型结构改进
    > 小幅调参和美化
```

例如，模型已经出现同一孕妇跨训练集和测试集的问题，此时换成更强的分类器没有意义；种植模型漏掉轮作要求时，增加模拟次数也不能补救。

**停止改进的条件：** 新方案不能稳定优于基线、解释成本明显增加、计算超时，或已经侵占必要的检查和提交时间。保留已验证版本，不以“复杂”代替“更好”。

## 3. 第一步：把题目拆成可验收的任务

### 3.1 三遍读题，各做一件事

**第一遍：确定最终交付物。**

逐问标出动词与名词：分析什么、预测什么、给出什么方案、比较什么、是否必须填指定表格。

**第二遍：提取硬条件。**

记录对象、时间范围、单位、可观测信息、约束、特殊值含义、附件之间的关系。

**第三遍：找歧义和依赖。**

区分三类信息：

| 类别 | 例子 | 处理方式 |
|---|---|---|
| 题面明确事实 | 某种资源容量、必须提交的年份和模板 | 原样落实，不能用假设否定 |
| 需要估计的参数 | 需求量、供应波动、检测达标概率 | 从允许的数据中估计，说明方法与误差 |
| 需要补充的假设 | 缺货成本、未知分布、管理阈值 | 解释理由，必要时比较多种取值 |

“所有数据准确无误”“忽略一切其他因素”通常不是有帮助的假设。假设应说明**具体忽略了什么、为什么能忽略、可能带来何种偏差**。

### 3.2 建立“逐问任务卡”

每问开工前填好下面的表，不要只说“这一问做预测”。

| 字段 | 要写的内容 |
|---|---|
| 任务 | 一句话说明本问要解决的问题 |
| 对象与粒度 | 企业、单品—日、文物采样点、孕妇—采血事件等 |
| 已知输入 | 附件、字段、时间范围、外部资料来源 |
| 决策时可得信息 | 做出预测或决策的当时，哪些信息已经知道 |
| 输出 | 表格、分类标签、区间、排序、最优方案、文字建议 |
| 必须满足的条件 | 容量、预算、库存、数量、适种、时点等 |
| 数学类型 | 描述、推断、预测、评价、优化，或它们的组合 |
| 基线 | 最简单可行的对照方法 |
| 验证 | 如何判断结论或方案可信 |
| 对后续问的影响 | 输出哪些参数给下一问，是否需要传递误差 |

### 3.3 画出小问之间的关系

常见结构是：

```text
数据审计 → 特征/规律分析 → 参数或需求估计 → 决策优化 → 风险与建议
```

但不必把每题强行串成一条线。有些小问是并列任务，有些评价指标只用于解释，不应该未经论证就成为优化目标。

例如：

- 供应商评分可以帮助筛选，但最优订购仍应检查供货能力和库存。
- 风险分类可以给信贷策略提供参数，但类别编号不能直接当连续风险数值。
- 商品销售相关性不能直接当作价格变化的因果效应。

### 3.4 赛前模拟如何选题

如果在 A/B/C 之间选择，建议队内用同一张表比较：

1. 能否在短时间内说清每问的输出？
2. 关键数据是否可读、可解释？
3. 是否有至少一套能落地的核心方法？
4. 最难约束能否实现与验证？
5. 计算量和写作工作量是否匹配团队能力？

“C 题看起来数据多、所以简单”不是充分理由。

## 4. 第二步：数据审计，而不是先画相关性热力图

### 4.1 先明确“一行是什么”

同一张表可能包含：交易流水、周汇总、一次检测、一个样本点。模型的统计单位与原始数据行不一定一致。

- 发票流水先汇总到企业，再分析企业风险，不能把每张票当成独立企业。
- 同一孕妇的检测记录存在相关性，不能当成完全独立的人。
- 同一文物多个部位的采样既可能有共性，也可能存在部位差异。
- 多商品同一天的面板数据，不能简单按行切分来模拟“预测未来”。

### 4.2 建立数据字典和多表关系

至少记录：文件、工作表、字段、含义、单位、主键、缺失含义、可用时间。

连接表时明确一对一、一对多还是多对一。连接后检查：

- 行数是否异常增加；
- 是否出现无匹配商品或企业；
- 金额、数量等总量是否守恒；
- 同名字段是否具有相同口径。

**常见事故：** 成本表同一商品有多个日期，销量表却只按商品编号连接，造成每笔交易被重复多次，最后收入和利润一起虚高。

### 4.3 缺失、零值、异常值分开处理

| 情况 | 应先问的问题 | 可考虑的处理 |
|---|---|---|
| 空白 | 未检测到、未填写、不适用，还是确实缺测？ | 按题面解释；必要时标记、插补或单独建模 |
| 0 | 真正为零、未营业、未运输，还是编码占位？ | 保留业务区别，不统一替换成缺失 |
| 负数 | 退货、冲销，还是不可能的录入值？ | 先按业务核对，再决定处理 |
| 极端值 | 罕见真实事件、质量问题，还是单位错误？ | 核对来源，比较保留/稳健处理的影响 |
| 重复记录 | 重复录入，还是多次采样/重复实验？ | 按业务键判断，不能无条件去重 |

具体例子：

- 2021 年转运损耗率中的 0，题面说明为“没有运送”，不能当作无损运输参与平均。
- 2022 年成分空白表示“未检测到”；直接当真零或做微小值替换都需要解释。题面将成分总和在 85%—105% 的记录视为有效数据，应先执行这个口径。
- 2025 年女胎 Y 染色体字段为空白属于结构性不适用；X 染色体浓度估计可能为负，题面已明确，不能机械删除负值。

### 4.4 区分“规则清洗”与“从数据学习的预处理”

以下训练/测试隔离针对需要评估泛化能力的任务。对整批数据做描述统计，可以使用整批数据，但不能把这种描述结果当作样本外预测性能。

- 按题面固定单位换算、解析日期、识别重复键：可在划分数据前进行，但保留记录。
- 用样本均值填补、标准化、PCA、特征筛选、异常阈值学习：应只在训练集或每个训练折内拟合，再作用于验证/测试数据。
- 看完测试集表现后再挑异常值删除，会污染评估。

这是防止数据泄漏的重要边界，scikit-learn 官方文档也明确强调先划分数据、不要在测试集上 `fit`，并推荐使用 `Pipeline`。[技1]

### 4.5 数据审计的最小交付物

1. 数据字典与连接关系图。
2. 原始行数、处理后行数和变化原因。
3. 缺失、异常、重复和无匹配记录清单。
4. 关键总量核对表与单位表。
5. 可以重跑的清洗程序，而非只保留手改后的 Excel。

## 5. 第三步：根据“要回答什么”选择模型

### 5.1 模型选择速查表

| 目标 | 优先考虑的基线 | 可升级的方法 | 不能只凭什么下结论 |
|---|---|---|---|
| 描述分布与规律 | 分组统计、分位数、趋势图、箱线图 | 分布拟合、分层描述、季节分解 | 单张热力图或平均数 |
| 比较群体、分析关系 | 列联表、相关分析、简单回归 | 方差分析、非参数检验、广义线性/混合效应模型 | 一个 p 值；相关不等于因果 |
| 预测连续值 | 历史均值/同期值、线性回归 | 正则回归、树模型、指数平滑、ARIMA 等 | 训练集拟合优度 |
| 判定类别 | 多数类/业务规则、逻辑回归、小决策树 | 随机森林、梯度提升、SVM 等 | 总准确率；小样本一次随机切分 |
| 无标签分组 | 简单业务分组、层次聚类 | K-means、混合模型、其他合适聚类 | 聚类算法总能分出组，不代表存在真实类别 |
| 综合评价排序 | 明确指标与等权对照 | AHP、熵权、TOPSIS、主成分综合评价 | “客观赋权”四个字不代表权重客观正确 |
| 配置资源与制定方案 | 可行规则、枚举小问题 | 线性规划、混合整数规划、动态规划、非线性规划 | 一个高收益数字，必须检查约束 |
| 处理波动和风险 | 参数敏感性、少量典型情景 | 蒙特卡洛、随机/鲁棒优化、机会约束、CVaR | 随机生成的数据不自动等于真实分布 |
| 分析排队与流程 | 流量平衡、简单等待时间估计 | 排队模型、离散事件仿真 | 未验证到达/服务假设就套公式 |

**不必每种方法都出现。** 一道题通常只需要几种相互衔接的方法，重点是选择理由和证据。

### 5.2 先区分描述、预测和因果解释

“价格越高销量越低”可能是价格影响需求，也可能同时受季节、品种、品质和促销影响。

- 描述：历史数据呈现什么关系？
- 预测：在已知信息下，未来可能是多少？
- 因果：如果主动改变价格，会使需求改变多少？

回归预测准确不自动证明因果机制。没有足够识别条件时，可把估计关系用于**限定历史支持范围内的情景决策**，并报告局限；不要宣称已经证明调价的真实效果。

### 5.3 综合评价不是默认起手式

只有题目确实需要“把多个维度综合成一个评价结果”时，才考虑综合评价模型。

先回答：谁被评价？好坏由谁定义？指标是收益型、成本型还是区间最优型？指标有没有重复计量？权重变化会不会改变结论？

如果题目要求在预算内最大化利润，而利润和约束已明确，直接优化往往比“先给利润、风险、成本各赋一个权重再排名”更贴近问题。

### 5.4 复杂模型的进入条件

在升级模型前，至少说明：

1. 基线具体哪里失败？
2. 新模型解决的是非线性、交互、时序、重复测量，还是其他结构？
3. 样本量和标签质量是否支持复杂度？
4. 验证方式能否比较新旧方案？
5. 算法能否在剩余时间内运行、解释、复现？

没有明确必要性，不优先使用深度学习、复杂集成或多种智能优化算法的叠加。

## 6. 第四步：把现实规则写成数学模型

### 6.1 建模的基本组成

| 要素 | 必须明确的内容 |
|---|---|
| 集合与索引 | 企业、商品、地块、时间、场景分别用什么索引 |
| 已知参数 | 数据来源、单位、估计方法、是否有不确定性 |
| 状态变量 | 库存、累积状态、历史轮作状态等 |
| 决策变量 | 实际可以选择的量：订货量、价格、面积、是否选用等 |
| 输出/目标 | 误差最小、收益最大、风险最小，或其他明确定义 |
| 约束 | 预算、容量、物料平衡、整数、逻辑、时间等 |
| 假设 | 为可解性或数据限制做出的简化 |

最重要的三个检查：

- **量纲一致：** 元/千克乘千克才是元，百分数与小数不能混用。
- **守恒成立：** 库存、物流、土地面积等不能凭空产生或消失。
- **信息可得：** 决策不能提前知道未来需求、价格或检测结果。

### 6.2 一个贯穿示例：从销售记录到补货方案

以下是**教学用简化问题**，不是 2023 年 C 题的完整模型或数值答案。

假设：单日经营；价格暂时固定；已估计每种商品当日需求；损耗发生在进货后、销售前，且损耗率已知；不考虑跨日库存。实际盘点损耗可能含不同环节，直接借用真实赛题损耗率前必须重新核对口径。

对商品 $i$，设：

- $x_i$：进货量，千克；
- $b_i\in\{0,1\}$：是否经营；
- $s_i$：销售量，千克；$u_i$：剩余可售商品量，千克；
- $c_i,p_i$：进价、售价，元/千克；
- $\ell_i$：销售前损耗率，取值在 $[0,1)$；
- $\widehat D_i$：估计需求；$v_i$：剩余商品残值单价；$h_i$：剩余商品处理成本单价。

目标：

$$
\max \Pi=\sum_i\left[p_i s_i+v_i u_i-c_i x_i-h_i u_i\right].
$$

约束：

$$
\begin{aligned}
&s_i+u_i=(1-\ell_i)x_i, &&\text{可售量平衡},\\
&0\le s_i\le\widehat D_i,\quad u_i\ge0, &&\text{销售不超过需求},\\
&m_i b_i\le x_i\le M_i b_i, &&\text{选中才经营，满足最小/最大量},\\
&L\le\sum_i b_i\le U, &&\text{经营品种数限制},\\
&\sum_i c_i x_i\le B, &&\text{采购预算限制}.
\end{aligned}
$$

其中 $m_i,M_i,L,U,B$ 需要由题意、业务依据或明确假设给出，不能为得到漂亮结果随意设定。预算约束只是本例展示常见约束的方式，并非声称 2023 题面给出了预算。

在售价高于剩余品净残值，即 $p_i>v_i-h_i$ 时，目标会优先销售可满足需求的商品。固定参数后，这是一个可以使用混合整数线性规划处理的模型。

**手工核验一个单品：** 假设售价 6 元/千克、进价 3 元/千克、销售前损耗率 10%、需求 90 千克，残值与处理费均为 0，其他约束不限制。

- 进货 100 千克，可售 90 千克，收入 540 元，成本 300 元，利润 240 元。
- 进货 120 千克，可售 108 千克，仍只售 90 千克，利润为 540−360＝180 元。

这里已经通过可售量扣除了损耗，不应再把同一部分货值重复扣一遍。计算机程序应能重现这样的手算例子。

### 6.3 价格也要决策时，模型发生什么变化

当 $p_i$ 也是决策变量时，需求会变成 $\widehat D_i(p_i,z_i)$，其中 $z_i$ 是时间、商品等条件。

建议按难度逐步推进：

1. 固定价格，只优化补货，先确保量与成本口径正确。
2. 对有业务依据、处于数据支持范围内的有限候选价格做枚举或离散化。
3. 如确有必要，再处理连续价格下的非线性或混合整数非线性模型。

不要让线性需求函数在远离历史价格范围处任意外推，也不要把历史销量直接当作“不受库存限制的真实需求”。

### 6.4 不确定性怎样进入模型

设需求、成本等在情景 $\omega$ 下不同，可以优化平均利润：

$$
\max \sum_{\omega=1}^{S}w_\omega\Pi(x;\omega),\qquad
w_\omega\ge0,\quad\sum_\omega w_\omega=1.
$$

重点不只是“抽多少次随机数”，而是：

- 情景来自历史重采样、题面范围还是主观设定？
- 情景之间哪些参数相关？
- 哪些决策必须提前做，哪些可以事后调整？
- 采用的概率有何依据？若没有，是否更适合区间/稳健分析？

**避免预知未来：** 如果进货必须在需求实现前决定，各情景应共享同一个进货方案；不能每个情景单独得到最优进货量后，把平均利润说成现实可获得利润。后者更接近“完美信息下的参考上界”。多年种植同样要说明一次性计划还是逐年更新，按相同信息条件比较。

### 6.5 2024、2025 两类题的特别提醒

**2024 种植：** 将变量展开到地块—作物—季节—年份，逐条落实适种、季数、面积、重茬和豆类要求。连续面积的三年累计豆类面积约束，未必能保证“每一部分土地三年内都种过豆类”；若用这种聚合近似，应说明，或用地块细分、轮作序列保证覆盖。不能把“种过极小面积豆类”冒充整块土地都满足要求。

**2025 NIPT：** 孕妇、采血事件、检测记录是不同层次；测序重复主要反映检测误差，不等同于额外独立孕妇。最早观测到达标的孕周不一定是真正首次达标时间；观察期内未达标的个体可能构成删失。第 4 问题面指定 AB 列作为判定结果，AE 是出生后结果，不能偷换标签，也不能作为检测时的输入。题面阈值仅用于赛题建模，不能把比赛模型宣传为临床诊断方案。

## 7. 第五步：求解与实现时先检查什么

### 7.1 从小规模可核验实例开始

不要一开始就把所有商品、年份和情景放进模型。

推荐顺序：

1. 一到两个对象、一个时段，手工计算。
2. 小规模枚举，与求解器比较。
3. 增加时间维度和业务约束。
4. 扩展到全部数据。
5. 最后增加不确定性和复杂目标。

这样可以把“公式错误”“索引错位”“求解器问题”分开定位。

### 7.2 优化程序返回数值不等于求解成功

至少报告：

- 求解器及版本、时间限制和停止条件；
- 求解状态：最优、可行但未证最优、不可行、无界或异常；
- 目标值、求解界和最优间隙（求解器提供时）；
- 最大约束违反量、整数误差、运行时间。

MILP 求解器的 `status`、`success`、`mip_gap` 等字段有不同含义，不能忽略状态只读取变量。[技3]

非线性求解器可能只给局部解；遗传算法等启发式搜索通常不提供全局最优证明。应写“得到的可行方案”“在所比较方案中最优”或“在指定求解容差下达到最优”，不要扩大结论。

### 7.3 不可行时的排查顺序

1. 单位和参数范围是否正确。
2. 初始库存/初始轮作状态是否遗漏。
3. 约束方向、上下界、索引是否写反。
4. 题意中的软要求是否被擅自变成过强硬约束。
5. 小规模实例是否也不可行。
6. 分组开启约束，定位冲突；若求解器支持，可用冲突分析。

松弛变量可以用于诊断缺口，但不能偷偷放宽硬约束后继续称“满足原题全部要求”。

## 8. 第六步：验证必须与问题类型相匹配

### 8.1 预测问题

必须先定义未来使用方式，再决定划分方式：

| 数据/使用场景 | 推荐验证方式 |
|---|---|
| 近似独立同分布的横截面样本 | 留出集或 K 折交叉验证 |
| 同一企业、文物、孕妇有多条记录，要推广到新对象 | 按对象分组划分，不让同一对象跨集合 |
| 用历史预测未来 | 按时间前后划分、滚动回测 |
| 既有对象重复又有时间约束 | 按实际部署设计同时约束对象和时间的划分，不盲用单一切分器 |

`GroupKFold` 解决组别不重叠；`TimeSeriesSplit` 面向有序时间数据。它们并不自动解决所有业务泄漏，且按等时距样本使用时间切分器时才容易保证各折时长可比。[技2]

指标按任务选择：

- 回归：MAE、RMSE；必要时给分组误差和区间覆盖率。真实值接近 0 时，MAPE 容易失真。
- 分类：混淆矩阵、召回率、精确率、F1；不平衡数据考虑 PR 曲线/平均精确率，概率用于决策时检查校准。
- 时间预测：与“上一期”“上一周同日”等朴素基线比较，模拟真实预测跨度。

调整特征、模型、阈值和超参数应在训练/验证阶段完成。**测试集不是调参工具。** 小样本可使用嵌套交叉验证等方式，但不要用形式复杂的验证掩盖有效样本很少的事实。

### 8.2 推断与解释问题

- 报告样本量、效应大小和置信区间，不只写“显著”。
- 说明独立性、方差、分布或模型结构假设。
- 大量检验要考虑多重比较，而不是只挑显著结果。
- 重复测量应考虑混合效应、聚类稳健标准误或按对象重采样等合适处理。
- 混杂、选择偏差和不可识别性应在结论中体现。

“不显著”不等于证明没有关系，“相关系数高”不等于证明因果。

### 8.3 聚类与综合评价

聚类可以检查轮廓系数、样本重采样稳定性、不同初始化的变化及领域可解释性；没有外部真值标签时，不能报告所谓“分类准确率”。

评价排序可以检查：

- 等权与其他合理权重下的排名变化；
- 删除某个指标后的变化；
- 标准化方法变化后的变化；
- 排名前若干对象的稳定程度。

### 8.4 优化决策

验证至少分两层：

**数学层：** 所有约束、变量范围、物料平衡、目标计算、求解状态是否正确。

**业务层：** 与现状或可行基线相比是否改善，极端情况下是否仍可执行，模型遗漏是否可能改变方案。

对于“先预测、后优化”，不能只比较预测 MAE；应在独立回测/测试情景下比较最终利润、缺货率、风险、库存等。误差更小的模型，不一定生成更好的决策。

## 9. 第七步：区分三种不同的可靠性工作

| 工作 | 回答的问题 | 例子 |
|---|---|---|
| 模型/结果验证 | 当前结果是否与数据、约束、留出样本一致 | 预测误差、约束审计、小例子枚举 |
| 敏感性分析 | 改一个设定，结果如何变化 | 成本上升、权重变化、BMI 分组边界扰动 |
| 不确定性分析 | 参数或观测本身有多不确定，如何传播到结论 | Bootstrap 区间、预测区间、情景下收益分布 |

建议至少选择**最可能改变结论的 2—3 个因素**，而不是机械地对所有参数统一上下浮动 10%。

可执行流程：

1. 选关键参数或假设，解释扰动范围来源。
2. 设计单因素与少量联合变化。
3. 记录结果值，也记录方案结构是否变化。
4. 找出使结论反转的阈值。
5. 说明应补充什么数据来减少这一不确定性。

注意：

- 重复测量数据做 Bootstrap 时，通常需要按独立对象抽样；直接抽检测记录会低估不确定性。
- 时间序列重采样应保留相应依赖结构，不能默认逐行独立抽样。
- 模拟分布是建模假设，不应伪装成观测事实。
- 在同一组随机情景下比较方案，再用独立生成的评估情景检查，可减少不公平比较和情景过拟合。

## 10. 第八步：把结果组织成论文，而不是复制软件输出

### 10.1 每问的最小论证链

```text
本问要解决什么
→ 为什么选择这个模型
→ 变量、假设、公式和约束
→ 参数怎样获得、模型怎样求解
→ 得到了哪些具体结果
→ 怎样检验
→ 结果的含义与局限
```

结果表应该让读者无需读程序就知道：对象是什么、单位是什么、对应哪一问、是否是最终方案。

### 10.2 推荐正文内容组织

以下是内容组织建议，不是官方规定必须使用的固定标题：

1. 问题重述与任务分解。
2. 分析思路、必要假设与符号。
3. 数据处理和关键发现。
4. 各问模型的建立、求解、结果与检验。
5. 敏感性/不确定性分析及模型评价。
6. AI 工具使用声明。
7. 参考文献。
8. 附录和支撑材料清单。

摘要最后重写，逐问概括**方法、关键结果、结论**，只填实际计算过的数字。不必在摘要堆满算法名称，也不要为了显得严谨捏造误差、显著性或提升比例。

### 10.3 图表选择应服务于论点

| 想说明的结论 | 合适图表 |
|---|---|
| 分布偏态与异常 | 直方图、箱线图、分位数表 |
| 时间趋势和预测 | 带时间轴的折线图、预测区间图 |
| 分类错在哪里 | 混淆矩阵、PR/ROC 曲线、分组表现表 |
| 方案如何分配资源 | 分配表、时间计划图、适当的热力图 |
| 稳健性如何 | 参数—结果曲线、情景分布、区间图 |

每张图说明数据范围、坐标轴、单位、图例及主要结论。不能以绘图数量代替分析。

## 11. 团队协作与比赛时间安排

### 11.1 三种角色是职责划分，不是信息隔离

| 工作 | 建模手主责 | 编程手主责 | 论文手主责 |
|---|---|---|---|
| 读题与拆题 | 任务、假设、约束 | 数据可行性、实现难点 | 输出要求、论证结构 |
| 数据处理 | 业务口径判断 | 清洗、汇总、审计 | 记录规则和来源 |
| 模型建立 | 变量、公式、方法选择 | 小例子实现、复杂度反馈 | 结构化表达、符号一致 |
| 验证 | 检验设计、结论边界 | 实验、约束检查、复现 | 证据整理、避免过度结论 |
| 定稿提交 | 内容复核 | 代码、结果文件、环境 | 版式、匿名、材料完整性 |

每位成员都必须理解核心模型。不能出现建模手不知道代码实际做什么、编程手不知道约束来源、论文手不知道数字对应哪个版本的情况。

### 11.2 统一交接格式

每个模型建立一张交接卡：

```text
模型版本 / 对应小问：
输入文件与字段 / 粒度 / 单位：
可用信息截止时点：
变量 / 目标函数 / 约束：
预处理与参数估计规则：
基线与验证切分：
预期输出表和图：
必须通过的手算例子与检查：
已知局限 / 允许的近似：
```

编程手返回：运行编号、配置、输入版本、求解状态、指标、结果路径、异常与风险。论文使用这些结果文件，而不是聊天截图中未经确认的数字。

### 11.3 以约三天赛程为例安排里程碑

官网介绍从 2019 年起竞赛通常为周四 18:00 至周日 20:00，即约 74 小时；**实际起止、提交哈希和文件上传窗口必须查当年通知，不能由下表推定**。[时间]

| 累计时间（演练示例） | 主目标 | 必须留下的成果 |
|---|---|---|
| 0—4 小时 | 选题、逐问拆解、读附件 | 任务卡、题意疑点、数据字典初稿 |
| 4—12 小时 | 数据审计、探索、建模框架 | 干净数据、关键图、数学模型草案 |
| 12—26 小时 | 主要小问的基线运行 | 每问的初步答案、代码、基本检查 |
| 26—46 小时 | 打通各问、完成主模型 | 完整结果表、约束审计、主体论证 |
| 46—60 小时 | 验证与有限改进 | 回测、敏感性、对照与局限 |
| 60 小时至结束前 6 小时 | 冻结主要模型、整合论文 | 定稿结果、摘要、图表与引用 |
| 最后约 6 小时 | 复现、格式、匿名、打包提交 | 可交付文件、检查记录、提交确认 |

论文从第一天开始搭结构和记录，不等全部计算结束才写。安排轮换休息；重要结论、提交文件和关键约束尽量由两人交叉检查。

若进度落后，优先减少无收益的模型比较、图表装饰和调参，不删除硬约束、不编造结果。

## 12. 2026 年规则如何影响解题流程

以下内容依据本地规则原文及官网对应页面核对，不用旧讲座中的地区性要求替代全国规定。[规2][规3][规4]

### 12.1 独立完成与检索边界

- 赛前可以练真题、交流方法、阅读优秀论文。
- 赛中必须由本队独立完成；不得与队外人员交流赛题，指导教师也不得提供解题指导。
- 2026 参赛规则禁止在相关交流平台浏览、发布或讨论与赛题有关的内容，列举平台包括 GitHub、CSDN、知乎等。
- 不把“可以查公开资料”理解为“可以看当届解题帖、代码仓库或直播”。算法文档、背景资料的使用仍须服从当年规则，并规范引用。
- 团队版本管理优先使用本地 Git 和合规的队内离线交接；不要在赛中公开或通过交流平台分发赛题代码、结果和讨论。

### 12.2 AI 是辅助，不能替代人工责任

2026 年试行规定要求：

1. 核心建模与分析由参赛队主导，对 AI 参与内容逐项人工审查核实。
2. **无论是否使用 AI，都在参考文献之前设置“AI 工具使用声明”**，按官方两种声明择一。
3. 使用 AI 的作品，在支撑材料中提交文件名为 `AI 工具使用详情.pdf` 的说明。
4. 记录工具名称与版本/型号、使用目的与环节、主要提示和过程、采纳修改与核验情况；语言润色适用原文所述核验情况说明的例外。

建议从一开始就保留使用日志，而不是交卷前凭记忆补写。AI 生成的文献要核实存在性，生成的代码要实际运行，生成的数字必须由真实计算支持。

### 12.3 论文、代码、匿名与提交

- 全国格式规范要求正文不要目录，正文不超过 30 页；摘要含标题与关键词，原则上不超过一页；附录页数不限。**本备战文档不是参赛论文，不受其章节布局约束。**
- 电子论文首页为摘要页，不放承诺书和编号专用页；纸质版另有要求。
- 全国允许 PDF 或 Word，建议 PDF；各赛区可增加要求。电子论文文件大小不超过 20MB。
- 附录应包含支撑材料清单和建模所用全部完整、可运行源程序；必要源码缺失、不能运行或与论文结果不符都可能影响评奖资格。
- 支撑材料也应包含必要源码、所使用的自主查阅数据等；题目提供的原始数据按规范无需重复装入。规范要求使用 WinRAR 压缩为 RAR/ZIP，大小不超过 20MB。
- 论文和支撑材料不得暴露队员、学校、赛区身份；检查正文、代码注释、路径、文件名、文件属性及日志。
- 指定结果模板、文件名和数值精度要求逐项核对；定稿后按当年流程提交对应的哈希与文件。提交哈希后再改文件，必须按允许窗口重新处理，不能认为“内容几乎一样”就无需检查。

本目录旧版 `全国大学生数学建模竞赛论文格式规范.doc` 和往年格式文件适合研究历史，不应覆盖 2026 年现行文件。

## 13. 最终验收清单

### 题意与模型

- [ ] 每问要求的全部对象、年份、日期、情景和输出都已覆盖。
- [ ] 题面事实、估计参数、额外假设分开记录。
- [ ] 数学变量、程序变量和论文符号一致。
- [ ] 目标函数有业务意义，关键硬约束没有遗漏。
- [ ] 决策与预测没有使用当时不可得的信息。

### 数据与验证

- [ ] 主键、连接关系、单位、缺失含义、特殊值已核对。
- [ ] 规则清洗与需学习的预处理边界明确。
- [ ] 时间依赖、对象重复、类别不平衡得到合理处理。
- [ ] 有基线；验证不是只看训练效果。
- [ ] 优化方案经过独立约束审计，求解状态如实报告。
- [ ] 有针对关键不确定性或假设的分析。

### 写作与交付

- [ ] 结论由实际输出支持，没有虚构数据、文献、精度或最优性。
- [ ] 主要结果在正文给出，图表有单位、编号和解释。
- [ ] 论文、结果模板、代码使用同一已冻结版本。
- [ ] 从原始输入重新运行，能够复现主要结果。
- [ ] 源码、支撑材料清单、引用、AI 声明与详情符合要求。
- [ ] 完成匿名、页数、大小、格式、文件名与提交确认检查。

**一句话总结：先把题意和数据做对，再把模型做完整，最后用验证证明结果可信。**
