## 1. 编程手真正负责什么

### 1.1 六条主线

1. **数据工程：** 附件读取、多表连接、清洗、汇总、特征构造。
2. **数学实现：** 将公式、约束和算法变成正确代码。
3. **实验设计落实：** 时间/对象切分、基线、调参、检验与比较。
4. **结果审计：** 单位、范围、约束、求解状态和异常检查。
5. **可视化与交接：** 输出可用于论文的表、图、配置和结果说明。
6. **复现与提交：** 固定环境和版本，从原始数据重跑，按模板导出。

代码运行成功，只说明执行过程中没有触发异常；不证明读对工作表、公式正确、没有数据泄漏或方案可行。

### 1.2 必须懂多少数学

至少理解：

- 均值、方差、分位数、相关、置信区间。
- 回归、分类、损失函数、过拟合、交叉验证。
- 决策变量、目标函数、线性/整数约束。
- 随机模拟、参数敏感性、最优解与可行解的区别。

如果不理解训练集与测试集，无法可靠地实现机器学习；如果不理解约束，无法判断优化求解是否完成。

### 1.3 先拿到交接卡，再实现

向建模手确认：

```text
小问与模型版本：
输入数据 / 主键 / 统计粒度 / 单位：
预测或决策时可用的信息：
预处理规则与参数来源：
变量 / 目标 / 约束 / 允许近似：
基线 / 验证切分 / 指标：
手算小例子 / 必须满足的断言：
输出文件、表格、图和精度要求：
```

遇到歧义应反馈，不要为了让程序能跑擅自修改业务约束。

## 3. 基础编程：先能写稳定脚本

### 3.1 Python 最低能力清单

- 变量、数值、字符串、列表、字典、集合。
- 条件、循环、函数、参数、返回值。
- 文件读写、编码、路径与相对路径。
- 异常处理：出错时保留原因，不用 `except: pass` 吞掉问题。
- 模块导入、虚拟环境、命令行运行。
- 调试器、断点、日志、基本测试。

推荐标准库：`pathlib`、`json`、`csv`、`re`、`logging`、`argparse`、`hashlib`、`datetime`、`time`。

### 3.2 NumPy 最容易导致静默错误的地方

- `(n,)`、`(n, 1)`、`(1, n)` 不是同一维度。
- 广播可能让错误表达式仍然运行，甚至变成一个意外的 $n\times n$ 矩阵。
- `*` 是逐元素乘法，`@` 才是矩阵乘法。
- 布尔索引、视图/复制、整数与浮点类型需明确。
- `NaN`、无穷值、除零和溢出应显式检查。

**训练：** 用很小的数组手算矩阵乘法和广播结果，关键函数加入形状断言。不要直接在大型数组上“看结果好像合理”。

### 3.3 编程题练什么，不必练什么

C 题编程手通常更需要表格、数值、优化与实验能力，不必先刷大量复杂算法竞赛题。仍建议练：

- 字符串解析与字典映射。
- 排序、分组、集合与去重规则。
- 简单枚举、贪心和动态规划。
- 时间复杂度、空间复杂度的基本判断。

能够估计“商品×日期×情景”的规模，往往比背一种冷门数据结构更实用。

## 4. 数据处理：C 题最容易花掉大量时间的环节

### 4.1 先盘点文件与工作表

不要默认第一个工作表就是要用的数据，也不要默认第一行一定是表头。

读取前记录：

- 文件名、工作表名、表头起始行和有效区域。
- 合并单元格、隐藏行列、备注行、汇总行。
- 字段含义、单位、主键、日期范围。
- 编号是否有前导零、百分数实际存储为小数还是文本。
- `.xlsx`、旧 `.xls` 和 CSV 的读取依赖不同；`openpyxl` 不负责旧 `.xls`。

遇到公式型单元格，要分清公式与缓存计算值；`openpyxl` 本身不是 Excel 公式计算引擎。赛前就演练有公式模板的处理方式。

### 4.2 pandas 必须熟练的操作

| 场景 | 常用能力 |
|---|---|
| 查看结构 | `shape`、`dtypes`、`head`、`info`、唯一值统计 |
| 缺失与类型 | `isna`、`to_numeric`、`to_datetime`、字符串处理 |
| 主键与重复 | `duplicated`、按业务键核对 |
| 汇总 | `groupby`、`agg`、`transform`、`value_counts` |

### 4.3 多表连接片段：连接后检查，不只看是否报错

下面是**自定义字段名的示例**，不是赛题实际字段。假设已准备 `transactions.xlsx` 和 `products.xlsx`，分别包含流水与唯一商品主表。

```python
# 示例 A：明确多对一连接，并核对行数、匹配情况和数量总量。
from pathlib import Path
import math
import pandas as pd

raw = Path("data/raw")
tx = pd.read_excel(
    raw / "transactions.xlsx", sheet_name="transactions",
    dtype={"item_id": "string"},
)
products = pd.read_excel(
    raw / "products.xlsx", sheet_name="products",
    dtype={"item_id": "string"},
)

assert {"item_id", "quantity_kg"}.issubset(tx.columns)
assert {"item_id", "category"}.issubset(products.columns)
for frame in (tx, products):
    assert frame["item_id"].notna().all(), "商品键缺失"
    frame["item_id"] = frame["item_id"].str.strip()
    assert frame["item_id"].ne("").all(), "商品键为空字符串"
assert not products["item_id"].duplicated().any(), "商品主表键不唯一"

tx["quantity_kg"] = pd.to_numeric(tx["quantity_kg"], errors="raise")
assert tx["quantity_kg"].notna().all(), "数量缺失，需要先确认口径"
row_count = len(tx)
quantity_total = tx["quantity_kg"].sum()

joined = tx.merge(
    products[["item_id", "category"]],
    on="item_id", how="left", validate="many_to_one", indicator=True,
)
assert len(joined) == row_count, "连接改变了流水行数"
assert joined["_merge"].eq("both").all(), "存在未匹配商品"
assert math.isclose(
    joined["quantity_kg"].sum(), quantity_total,
    rel_tol=1e-12, abs_tol=1e-8,
), "连接前后数量不守恒"
```

这些 `assert` 是演示检查意图；正式关键校验可改成显式抛出异常，以免在使用 Python 优化运行选项时断言被移除。数值容差应按单位、量级和累计误差选择。

成本表若是“商品—日期”粒度，就必须按对应键连接，不能照抄这个仅按商品的例子。发现无匹配时应导出异常清单并调查，而不是直接删掉这些行。

### 4.4 缺失与异常的真实含义

- 2020 信贷票据中的负数可能是退货冲销，不能全部删掉。
- 2021 损耗率 0 表示没有运送，不应当作一次完美运输。
- 2022 成分未检出不同于普通缺失；先按题面的有效总和范围筛查。
- 2023 没有某日流水，不自动等于真实需求为 0。
- 2025 女胎 Y 字段空白是结构性不适用；X 浓度可能为负已由题面说明。

**缺失特征和缺失标签分开处理。** 特征可在合理假设下插补；监督目标没有标签时，不能通过随意补值把它当作真实监督样本。

### 4.5 孕周解析：用一个小函数避免数量级错误

2025 C 的孕周为“周数+天数”。例如 12 周 3 天为 $12+3/7$ 周，**不是 12.3 周**。

以下函数仅接受示例约定的三种文本格式；真实附件出现其他格式时，应记录并明确扩展，不猜测含义。

```python
# 示例 B：纯标准库，可独立运行的孕周解析与测试。
import re
import math


def parse_gestational_week(value):
    if not isinstance(value, str):
        raise TypeError("孕周应为明确的周+天文本，不自动解释数字")
    text = value.strip().lower()
    match = re.fullmatch(r"(\d+)\s*(?:w\+|\+|周)\s*([0-6])(?:天)?", text)
    if match is None:
        raise ValueError(f"无法识别孕周格式：{value!r}")
    weeks, days = map(int, match.groups())
    return weeks + days / 7.0


assert math.isclose(parse_gestational_week("12w+3"), 12 + 3 / 7)
assert math.isclose(parse_gestational_week("12+3"), 12 + 3 / 7)
assert math.isclose(parse_gestational_week("12周3天"), 12 + 3 / 7)
assert math.isclose(parse_gestational_week("12W+6"), 12 + 6 / 7)
for invalid in ["12w+7", "12.3", "未知", ""]:
    try:
        parse_gestational_week(invalid)
    except ValueError:
        pass
    else:
        raise AssertionError(f"本应拒绝：{invalid!r}")
```

解析成功不代表医学或题意范围合理。是否超出分析范围、缺失怎么处理、不同日期计算的孕周是否矛盾，应作为单独的业务审计。

### 4.6 为清洗留下证据

建议产出：

- 原始文件清单及 SHA-256 等内容哈希。
- 清洗规则版本、字段映射和数据字典。

## 5. 特征工程：懂业务和信息时点，比多造变量更重要

### 5.1 按实体构造特征

| 场景 | 可考虑的特征 | 必须核对的边界 |
|---|---|---|
| 企业风险 | 交易规模、波动、退货、上下游集中度 | 指标时间窗口、票据有效性、评级与标签关系 |
| 供应商 | 平均供货、履约偏差、波动、持续供货比例 | 无订单周与无供货周不同，分母为零需处理 |
| 商品销量 | 星期、月份、历史销量、价格、促销 | 未来价格是否已知、销量受缺货限制 |
| 玻璃成分 | 合理的比例/对数比、风化、部位信息 | 总和约束、未检出、同文物多点 |
| NIPT | 检测时可得的孕周、BMI、测序质量等 | 孕妇与采血事件重复；出生后变量不允许提前用 |

### 5.2 时间特征必须先滞后，再统计

自定义日面板数据示例，假设每个商品每个日期至多一行：

```python
# 示例 C：此片段要求 daily 已经存在，且日历完整性已核对。
daily = daily.sort_values(["item_id", "date"]).copy()
assert not daily.duplicated(["item_id", "date"]).any()
daily["lag_1"] = daily.groupby("item_id")["sales_kg"].shift(1)
daily["mean_previous_7_rows"] = daily.groupby("item_id")["sales_kg"].transform(
    lambda series: series.shift(1).rolling(7, min_periods=7).mean()
)
```

这里写成 `previous_7_rows` 是有意的：若日期不连续，7 行不等于 7 天。先明确缺失日期的业务含义并补齐日历，或者使用正确的时间窗口方法。

更重要的是，这段全历史特征只适合对应信息条件的逐日单步回测；**一次性在截止日预测未来一周时，不能让测试周前几天的真实销量进入后几天特征**。应使用截止日前可知特征、直接多步预测，或递归使用预测值，并如实模拟更新方式。

### 5.3 最常见的泄漏检查

- 目标或目标变形是否混入特征？
- 是否使用了统计窗口之后的信息？
- 编号是否隐含标签、时间或采样批次？
- 是否先用全数据做筛选、插补、标准化或 PCA？
- 同一对象是否跨训练和测试？
- 数据增强或过采样是否在划分前完成？
- 是否把第 4 问的 AE 出生后信息用于 NIPT 检测时判定？
- 是否按测试集成绩决定删哪些异常或修改哪个阈值？

`Pipeline` 能防止很多预处理泄漏，但不能自动识别错误特征和不合适的划分。[技1]

## 6. 机器学习与统计实现：先有可信基线

### 6.1 推荐掌握的 scikit-learn 能力

- `SimpleImputer`、`StandardScaler`、`OneHotEncoder`。
- `ColumnTransformer`、`Pipeline`。
- `DummyRegressor`、`DummyClassifier`。
- 线性/正则回归、逻辑回归、决策树、随机森林。
- `GroupKFold`、`GroupShuffleSplit`、`TimeSeriesSplit`；必要时使用分层分组切分。
- `cross_validate`、`GridSearchCV` 或有边界的随机搜索。
- MAE、RMSE、混淆矩阵、精确率、召回率、F1、ROC/PR 等。

先会正确比较两三个模型，再考虑扩大搜索。控制 `n_jobs`，避免交叉验证和模型内部同时开满线程导致资源争抢。

### 6.2 一个完整的“分组验证”训练示例

下面使用**人工生成的重复测量数据**，演示：对象级留出、训练折内预处理、同一折上比较基线、开发集选模型、测试集只评估一次。

它不是 NIPT 真实规律，不用于医学解释；回归模型这里只用于预测流程训练，不替代重复测量的统计推断模型。

```python
# 示例 D：需要 numpy、pandas、scikit-learn；数据完全合成。
import numpy as np
import pandas as pd
from sklearn.dummy import DummyRegressor
from sklearn.impute import SimpleImputer
from sklearn.linear_model import Ridge
from sklearn.metrics import mean_absolute_error, mean_squared_error
from sklearn.model_selection import (
    GroupKFold, GroupShuffleSplit, GridSearchCV, cross_val_score,
)
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(42)
n_subjects = 80
groups = np.repeat(np.arange(n_subjects), 3)
bmi = np.repeat(rng.uniform(20, 40, n_subjects), 3)
week = np.tile([12.0, 16.0, 20.0], n_subjects)
subject_effect = np.repeat(rng.normal(0, 0.003, n_subjects), 3)
y = (
    0.03 + 0.001 * (week - 12) - 0.0005 * (bmi - 28)
    + subject_effect + rng.normal(0, 0.002, len(groups))
)
X = pd.DataFrame({"bmi": bmi, "week": week})
X.loc[X.index[::17], "bmi"] = np.nan

outer = GroupShuffleSplit(n_splits=1, test_size=0.2, random_state=42)
dev_idx, test_idx = next(outer.split(X, y, groups=groups))
assert set(groups[dev_idx]).isdisjoint(set(groups[test_idx]))
X_dev, y_dev = X.iloc[dev_idx], y[dev_idx]
groups_dev = groups[dev_idx]

folds = list(GroupKFold(n_splits=5).split(X_dev, y_dev, groups_dev))
for train_idx, valid_idx in folds:
    assert set(groups_dev[train_idx]).isdisjoint(set(groups_dev[valid_idx]))

pipeline = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler()),
    ("model", Ridge()),
])
search = GridSearchCV(
    pipeline, {"model__alpha": [0.1, 1.0, 10.0]},
    scoring="neg_mean_absolute_error", cv=folds, n_jobs=1,
)
search.fit(X_dev, y_dev)

baseline = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("model", DummyRegressor(strategy="mean")),
])
baseline_scores = cross_val_score(
    baseline, X_dev, y_dev, cv=folds,
    scoring="neg_mean_absolute_error", n_jobs=1,
)

# 只根据开发集交叉验证选模型，不根据测试集反复调整。
if search.best_score_ >= baseline_scores.mean():
    final_model = search.best_estimator_  # 已在整个开发集上重新拟合
    selected = "ridge"
else:
    final_model = baseline.fit(X_dev, y_dev)
    selected = "mean_baseline"

pred = final_model.predict(X.iloc[test_idx])
print({
    "selected": selected,
    "development_cv_mae_ridge": float(-search.best_score_),
    "development_cv_mae_baseline": float(-baseline_scores.mean()),
    "test_mae": float(mean_absolute_error(y[test_idx], pred)),
    "test_rmse": float(np.sqrt(mean_squared_error(y[test_idx], pred))),
})
```

学完应能解释：

- 为什么编号只用于分组，不直接放进特征。
- 为什么不能在全部 X 上先插补和标准化。
- 为什么比较模型必须使用相同的验证折。
- 为什么开发集最佳交叉验证分数也可能乐观，最终留出用于评估完整选择过程。
- 如果数据还存在时间部署要求，这个单纯按对象留出的例子为什么还不够。

该例每个对象记录数相同；真实数据中次数不同时，还要考虑按对象加权或报告对象层面的指标。

### 6.3 分类的额外检查

- 每折的训练集/验证集有哪些类别，稀有类数量是否支持当前折数。
- 类别权重、采样和阈值在训练/验证阶段确定。
- 不仅输出标签，也按需要保留概率。
- 给出样本/对象数量、类别占比、混淆矩阵和指标。
- 验证折缺少正类时，部分指标无定义；不能填 0 或 1 掩盖问题，应调整方案或说明限制。
- 多分类、多标签、二分类不是同一任务。2025 AB 列需按题意明确是总体异常还是不同染色体异常，标签映射要记录，不把 AE 偷换成指定目标。

### 6.4 统计推断与机器学习工具不要混淆

scikit-learn 主要围绕预测流程；需要回归显著性、标准误、残差检验或混合效应时，可使用 statsmodels 等合适工具。

但输出了 p 值不代表假设自动成立。重复测量、异方差和多重检验应由建模手与编程手共同确定处理方法。

### 6.5 时间回测怎么实现才可靠

1. 定义预测截止日和预测跨度。
2. 按唯一日期安排折，确保同一天所有商品处于同一侧。
3. 每折仅使用截止日前可得数据拟合预处理和模型。
4. 严格模拟单步滚动或固定跨度多步预测。
5. 对重叠标签窗口、提前期等设置必要间隔，不能只依赖一个 `gap` 默认值。
6. 保存每个对象、日期、真实值、预测值、训练截止日和折编号。
7. 汇总总体及分组指标，并与同期/均值基线比较。

不要直接对多商品面板的“排序后每一行”使用 `TimeSeriesSplit`，否则同一天可能被切到两侧。该切分器的时间跨度可比性还涉及等时距条件。[技2]

## 7. 优化实现：必须同时会“求解”和“验解”

### 7.1 优先掌握的求解能力

| 类型 | 建议入口 | 重点检查 |
|---|---|---|
| 线性规划 | `scipy.optimize.linprog` | 目标方向、边界、状态、对偶信息的含义 |
| 混合整数线性规划 | `scipy.optimize.milp` 或一种建模库 | 整数标记、逻辑约束、时间限制、间隙 |
| 连续非线性 | `scipy.optimize.minimize` 等 | 初值、局部最优、梯度、尺度和可行性 |
| 小规模离散问题 | 枚举、动态规划 | 最优性可核验，作为复杂实现的对照 |
| 复杂启发式 | 按题选择 | 可行性保持、重复运行、停止条件、无全局证明 |

SciPy `milp` 的接口用于最小化；最大化收益通常将目标系数取负，并在输出时改回原始含义。[技3]

### 7.2 小 MILP 示例：求解后独立枚举核对

教学问题：生产两种产品，数量为非负整数 $x,y$，利润为 $3x+2y$；约束 $x+y\le4$、$2x+y\le5$。最优结果可手算，适合验收环境和符号。

```python
# 示例 E：需要 numpy、scipy；仅演示一个小整数规划。
import numpy as np
from scipy.optimize import Bounds, LinearConstraint, milp

profit = np.array([3.0, 2.0])
A = np.array([[1.0, 1.0], [2.0, 1.0]])
upper = np.array([4.0, 5.0])
result = milp(
    c=-profit,
    integrality=np.ones(2, dtype=int),
    bounds=Bounds(np.zeros(2), np.full(2, 4.0)),
    constraints=LinearConstraint(A, np.full(2, -np.inf), upper),
    options={"time_limit": 10.0, "mip_rel_gap": 0.0},
)
print({
    "status": result.status,
    "message": result.message,
    "mip_gap": getattr(result, "mip_gap", None),
})
if result.x is None:
    raise RuntimeError("没有可用解，不能继续导出方案")

solution = result.x
tol = 1e-7
assert np.isfinite(solution).all()
assert (solution >= -tol).all() and (solution <= 4.0 + tol).all()
assert np.max(np.abs(solution - np.rint(solution))) <= tol
assert (A @ solution <= upper + tol).all()

# 使用原始数学规则枚举，不依赖求解器矩阵计算来找最优对照。
feasible = [
    (x, y) for x in range(5) for y in range(5)
    if x + y <= 4 and 2 * x + y <= 5
]
best_profit = max(3 * x + 2 * y for x, y in feasible)
computed_profit = float(profit @ solution)
if not result.success:
    raise RuntimeError("本训练例未获求解器最优状态；实际问题应如实报告状态")
assert np.isclose(computed_profit, best_profit)
assert best_profit == 9
print({"solution": solution.tolist(), "profit": computed_profit})
```

这里的 9 是教学小例子的可枚举结论，不是真题成绩。正式大模型通常不能枚举全部方案，但应先用小实例确认约束和索引。

### 7.3 超时、不可行和最优性如何处理

- `success=False` 不一定表示没有可行解，可能达到时间限制；检查是否有解、可行性和求解界。
- 有变量数值不表示最优；如仅得到可行解，应如实报告当前目标与间隙。
- 不可行时先查单位、初始状态、边界、索引和约束冲突，不直接删除“麻烦的约束”。
- 无界往往提示遗漏关键资源或数量上界，也可能确实是模型定义问题。
- 浮点容差、MIP 间隙与全局最优证明不是同一个概念。
- 不把连续松弛解简单四舍五入当作整数可行解。

### 7.4 建立独立的方案检查器

求解代码与验解代码尽量分开；检查器读取最终方案表，按业务规则重新计算，而不是只复用求解矩阵。

建议输出约束审计表：

| 约束编号 | 对象/日期 | 左端计算值 | 界限 | 违反量 | 容差 | 是否通过 |
|---|---|---|---|---|---|---|
| 示例：预算 | 全部商品/某日 | 按最终表重算 | 题定预算 | 超出部分 | 按金额精度设定 | 真/假 |

至少检查：

- 非负、整数、0-1、上下界。
- 面积、容量、预算、数量约束。
- 期初—到货—消耗—期末的平衡。
- 适种、季数、重茬、历史轮作和豆类覆盖。
- 损耗和成本口径。
- **导出并舍入后的文件**是否仍然满足条件。

小规模模型通过检查，不等于完整模型通过；新增约束和数据扩容后都要重新审计。

## 8. 模拟与敏感性：可重现还要可解释

### 8.1 一个实验需要记录什么

- 改变哪个参数/假设，范围为何合理。
- 随机分布及其参数，是否保留相关性。
- 种子、抽样单位、情景数。
- 是固定方案做压力测试，还是每次重新优化。
- 每个情景下成本、收益、违反率、缺货等结果。
- 均值、分位数、尾部损失和方案变化。

区分两个问题：

1. 固定方案在不同环境下表现如何？
2. 如果在同样的信息条件下重新决策，方案如何变化？

若重新优化时让算法看见了原本未知的未来参数，就变成完美信息实验，应明确标注，不能与真实可执行策略混比。

### 8.2 随机数与并行

- NumPy 优先使用 `default_rng` 等明确的随机数生成器。
- sklearn 模型与随机切分器分别设置适当的 `random_state`。
- 并行情景不能在每个工作进程用相同种子反复生成同一批样本；使用明确的子种子/种子序列。
- 比较多个方案时使用相同评估情景，必要时再用另一批独立情景检验泛化。
- 固定种子只是复现条件之一；库版本、线程、硬件和求解器也会影响结果或末位小数。

### 8.3 抽样单位要正确

重复对象数据按孕妇/企业/文物等独立单位重采样，而不是默认逐记录重采样；时间序列考虑依赖结构。对测量误差的模拟，应明确是技术重复、个体差异还是时间变化，不能混成一个任意噪声项。

## 9. 可视化与结果导出

### 9.1 能稳定画好这些图就很实用

- 分布图、箱线图、散点图。
- 时间趋势与预测区间图。
- 分组对比图与适当的误差条。
- 混淆矩阵、PR/ROC 曲线。
- 资源分配、时间计划、参数敏感性图。

图要回答一个问题，不是展示“会调用一个绘图库”。

统一：单位、颜色语义、中文字体、字号、图例、图编号、有效小数位。字体来自机器已安装或合规可用的字体，不要依赖你电脑独有的路径。

线图/文字多的图可优先保存矢量 PDF/SVG，另备论文工具可用的 PNG；位图分辨率按最终版面确认。不要所有图都导出超大分辨率导致论文超 20MB。

### 9.2 每张图同时交一张数据表

给论文手的不是只有 `figure.png`，还应有：

- 生成图的数据表。
- 图的标题、单位、范围和主要结论。
- 对应小问、模型版本和运行编号。
- 是否包含预测区间，区间代表什么。

如果图来自随机一次运行，需说明随机性；不选择“最好看的一次”而隐去其他结果。

### 9.3 指定 Excel 模板的正确处理

1. 读取模板，列出工作表、行/列标签和待写单元格。
2. 建立明确的对象—年份—季节—单元格映射。
3. 填值，不擅自重排字段、重命名工作表或改变文件名。
4. 保存到新的输出路径，不覆盖原始模板。
5. 重新读取输出文件，检查维度、缺失、对象覆盖、总量和约束。
6. 检查是否存在公式缓存问题、科学计数法、编号丢失或错误精度。

2021 题面明确要求将订购和转运结果填入附件 A/B 并勿改文件名；2024 题面给出 `result1_1.xlsx`、`result1_2.xlsx`、`result2.xlsx`。提交契约应在开工时建立，而不是最后临时补。[题源]

## 10. 工程组织与一键复现

### 10.1 一个够用的项目结构

以下只是建议目录；按题目和团队习惯调整，不必为了工程化增加无用层次。

```text
solution/
├── README.md                  # 环境、输入位置、运行顺序、输出说明
├── requirements-lock.txt      # 经过测试的依赖版本
├── config.json                # 参数、种子、日期、容差、求解限时
├── data/
│   ├── raw/                   # 原始附件，只读；实际提交按规则处理
│   └── processed/             # 可由源码重新生成
├── notebooks/                 # 探索草稿，不作为唯一执行入口
├── src/
│   ├── data.py                # 读取、校验、清洗
│   ├── features.py            # 特征与时间边界
│   ├── models.py              # 训练与预测
│   ├── optimization.py        # 优化建模与求解
│   ├── validation.py          # 回测、独立约束检查
│   └── reporting.py           # 表、图、模板导出
├── tests/                     # 小实例与业务规则检查
├── outputs/
│   └── run_001/
│       ├── tables/
│       ├── figures/
│       ├── logs/
│       └── manifest.json      # 本次运行输入、配置、环境和输出记录
└── run_all.py                 # 完整入口
```

题目较小时可合并模块，关键是分清读取、处理、训练/求解、验证、导出，不要一个函数同时做所有事。

### 10.2 一键运行是什么标准

例如希望最终支持：

```bash
python run_all.py --config config.json
```

这要求团队实际实现该入口；本指南没有替你创建这些工程文件。合格流程应：

1. 检查输入存在、字段和结构符合要求。
2. 清洗与构造分析表。
3. 生成固定的训练/验证切分。
4. 训练/求解并保存状态。
5. 执行关键校验；失败时停止正式导出。
6. 导出全部论文主要数字、图、模板和清单。

原始题目数据可以由复现者按说明放在 `data/raw/`，不依赖你电脑上的绝对路径。

### 10.3 Notebook 的正确使用方式

Notebook 适合探索，不适合成为不可追踪的“魔法状态”：

- 不依赖乱序执行留下的变量。
- 在“重启内核并运行全部”后仍能重现结果。
- 稳定的清洗和求解逻辑迁移到函数或脚本。
- 删除输出不能影响计算；手工修改数据必须转成记录明确的步骤。
- 最终实验使用冻结配置，而不是某个没保存的单元格变量。

### 10.4 用运行清单避免“论文数字来自三个版本”

`manifest.json` 可记录：

```json
{
  "run_id": "run_001",
  "input_hashes": {},
  "config_file": "config.json",
  "seed": 42,
  "split_manifest": "tables/split_manifest.csv",
  "environment_file": "requirements-lock.txt",
  "solver_status": "record_actual_status_here",
  "outputs": []
}
```

这是字段结构示意；正式运行必须由程序填入真实哈希、状态、指标与输出列表，不把示意占位值当成完成的记录。内部代码版本可本地记录，但提交材料不要携带 `.git` 历史或身份信息。

建议每次正式运行生成独立目录，不覆盖旧结果。论文只使用明确标记的最终运行版本。

### 10.5 本地 Git 如何使用

- 赛前熟悉 `status`、`diff`、`add`、`commit`、`log` 和恢复指定版本。
- 小步保存，提交说明描述改变的模型或修复的错误。
- 大数据、虚拟环境、缓存和敏感信息不混进代码仓库。
- 同一文件避免多人同时改，先约定模块负责人。
- 赛中遵守独立完成和交流平台限制，不公开上传当届题目代码或讨论；本地 Git 不等于获得远程发布许可。

## 11. 测试与调试：用能暴露错误的小例子

### 11.1 四层检查

| 层次 | 检查对象 | 示例 |
|---|---|---|
| 数据契约 | 输入结构与业务口径 | 主键唯一、列存在、百分数范围、连接守恒 |
| 函数/公式 | 最小计算单元 | 孕周换算、损耗后可售量、利润计算 |
| 模型/方案 | 训练与优化结构 | 组别不重叠、无未来特征、所有硬约束通过 |
| 端到端 | 从原始输入到论文结果 | 全流程重跑、导出后重读、数字一致 |

### 11.2 应提前准备的最小测试集

- 缺失列、重复键、未匹配商品必须触发检查。
- 百分数 4% 应与小数 0.04 区分清楚。
- 孕周 `12w+3` 转换正确，非法天数拒绝。
- 一个商品的损耗与利润能与手算一致。
- 同一孕妇/文物不能跨训练与测试。
- 时间特征不使用目标日或更晚的观测。
- 预算减少、容量减少等变化下，方案仍接受约束审计。
- 小 MILP 与枚举结果一致。
- 指定模板对象和年份全部覆盖。
- 舍入导出后的方案仍满足规定精度下的约束。

测试不是只有“输入正常时有输出”，还要故意制造失败情况，确认程序不会静默产出错误答案。

### 11.3 出错时按证据排查

```text
保留原始报错和失败配置
→ 缩小到最小样本/实例
→ 检查输入与维度
→ 对照手算和业务规则
→ 定位最早出现差异的步骤
→ 最小修改
→ 重跑原失败用例与相关测试
→ 再运行完整任务
```

不要反复让 AI“重写全部代码”却不给报错、输入结构和预期行为；也不要为了消除异常随意 `fillna(0)`、截断负数、删除约束。

### 11.4 什么时候优化性能

先正确，再测量耗时，再优化瓶颈。

常用方法：

- 按需要读列和设置类型，避免重复读大 Excel。
- 用分组/向量化替代大量逐行操作，但先验证一致性。
- 缓存可重算中间结果，并用输入哈希避免过期缓存。
- 优化模型只创建业务允许的索引组合，减少无用变量。
- 大规模线性约束考虑稀疏矩阵，给 Big-M 合理上界。
- 先小数据调试，再全量；先少量情景检查，再扩大并观察稳定性。
- 有限调参，设置超时，保留已经验证的基线。

不要用更强硬件解决本质上的错误索引或无边界搜索。

## 12. 交接与比赛中的执行节奏

### 12.1 给队友的标准结果包

每问至少返回：

1. 一段方法与本次修改说明。
2. 输入版本、配置和运行编号。
3. 预测/决策主表，包含对象、日期、单位。
4. 指标表或约束审计表。
5. 论文可用图及对应图源数据。
6. 状态、失败项、局限与需要建模手决定的问题。
7. 精确的文件位置与复现命令。

不要只说“跑完了，效果不错”；更不能只发终端截图，让论文手手抄数字。

### 12.2 比赛中的优先级

1. 所有附件可读、口径正确。
2. 基线能端到端运行。
3. 关键约束、切分和目标正确。
4. 每问有可交付结果。
5. 再做必要的模型改进与性能优化。
6. 冻结主要结果，复现并导出。

每次重要改动都保留回滚版本。临近截止不引入没演练过的依赖、求解器或语言。

## 13. 2026 年代码、AI 与提交准备

本节依据当前全国规则，赛区和后续通知仍需核对。[规]

### 13.1 源码应能支持论文结果

- 论文附录包含建模所用全部完整、可运行源码和支撑材料清单。
- 支撑材料包含必要的可运行程序、自主查阅使用的数据和相关结果等。
- Excel/SPSS 等交互操作也应按规范提供可复现的命令或过程记录。
- 不只交模型二进制文件、Notebook 截图或最终 Excel。
- 不把失败代码、无用大型缓存和未经使用的模板打包冒充完整性。
- 不重复塞入大量题目原始数据和环境目录，按规则和必要性组织材料。

缺必要源码、不能运行或运行结果与论文不符，可能影响评奖资格。论文和支撑材料应使用同一冻结版本。

### 13.2 匿名检查的重点

检查：

- 用户名、学校名、队员名、队号和赛区信息。
- 绝对路径、代码注释、异常追踪、Notebook 输出。
- 文件/文件夹名、PDF/Office 作者属性、图片元数据。
- Git 历史、远程地址、环境变量、账号与 API 密钥。

不要把 `.git`、`.venv`、密钥、个人配置或身份相关日志加入提交包。匿名要求针对参赛身份，不是让你删掉题目要求的商品编号、地块编号或匿名样本代码。

### 13.3 AI 使用日志从第一天就记录

可用表格记录：时间、工具和版本、任务、主要提示、采纳内容、人工修改、核验动作、对应文件。

合理辅助例子：解释 API、定位已提供的报错、生成小测试、检查代码与公式是否一致。无论由谁生成，核心逻辑、结果和文献都由团队负责核验。

2026 年：

- 论文参考文献前必须有相应 AI 工具使用声明，未用也声明。
- 实际使用时，在支撑材料加入 `AI 工具使用详情.pdf`。
- 详情包括名称与版本/型号、目的与环节、提示/过程、采纳修改与核验情况等，按原文落实。

不要向外部工具发送账号密钥或不必要的个人信息。涉及医疗等数据时，注意数据最小化和使用边界。

### 13.4 最后一次打包流程

1. 冻结模型、代码、配置与论文。
2. 在干净执行状态下重跑，检查关键输出。
3. 按论文和支撑清单逐项核对文件。
4. 重读最终 Excel、打开最终论文检查排版与图表。
5. 检查电子论文首页、正文页数、引用、AI 声明与匿名。
6. 按全国与赛区要求生成论文和压缩材料，分别检查大小。
7. 按当年客户端流程生成/提交哈希和文件，保留对应冻结文件与确认记录。

全国 2026 规范：电子论文 PDF 或 Word（建议 PDF），不超过 20MB；支撑材料要求使用 WinRAR 压缩为 RAR/ZIP，不超过 20MB；正文不要目录、不超过 30 页。具体纸质要求、赛区格式、客户端、哈希和上传窗口不能照搬旧年份。

打开文件不一定改变哈希，但任何保存、自动保存或元数据修改都可能改变内容；提交后以冻结文件为准，不能仅凭文件名相同认为内容未变。

## 14. 八周编程训练计划

与建模手计划使用相同主题；平时每周可安排约 12—18 小时，限时整题模拟另计。基础薄弱时延长周期，不跳过数据与验证基本功。

| 周次 | 编程重点 | 联合练习 | 验收成果 |
|---|---|---|---|
| 第 1 周 | Python、NumPy、pandas、文件读写 | 读 2022 或 2023 附件 | 数据字典、类型/缺失/主键报告，可重跑清洗 |
| 第 2 周 | 绘图、回归、statsmodels 基础 | 关系模型与残差分析 | 同一数据口径下的图表、系数与验证结果 |
| 第 3 周 | Pipeline、分类、分组验证、聚类 | 2022 分类与亚类 | 基线与对照、分组切分、稳定性结果 |
| 第 4 周 | 日期、长宽表、滞后、滚动回测 | 2023 日销量与一周预测 | 不泄漏的回测预测明细与指标 |
| 第 5 周 | SciPy LP/MILP、索引、独立验解 | 2021 缩小版订购运输 | 手算/枚举一致，约束审计与模板导出 |
| 第 6 周 | 多期约束、场景、随机数和效率 | 2024 缩小版轮作与风险 | 期初状态正确，无前瞻信息，情景比较可重现 |
| 第 7 周 | 工程整合、日志、结果包 | 2023 等题 24—36 小时阶段模拟 | 全链条入口、论文主体所需结果与支撑草稿 |
| 第 8 周 | 完整模拟、复现、匿名与打包 | 一份尚未完整做过的真题 | 正式时长内交付，另一台队内机器复跑关键结果 |

### 只有两周时

- 1—3 天：Python/pandas、多表、日期、绘图、输入审计。
- 4—5 天：回归/分类基线、Pipeline、分组/时间验证。
- 6—7 天：小规模 LP/MILP、验解、Excel 模板写回。
- 8—10 天：和建模手打通一题，记录结果和失败点。
- 11—14 天：补致命短板、复现和提交演练；按可用时间安排限时模拟。

暂缓深度学习、多种工具链迁移和大规模超参搜索。

### 只剩两天时

**第一天：** 固定能用的环境；读真实附件；跑通一个回归/分类 Pipeline 和一个小 MILP；检查中文图与 Excel 导出；准备数据/约束审计函数。

**第二天：** 和队友演练一个小问的完整交接；把结果导入论文；复跑；检查规则与打包。准备备用电脑、输入副本和已有基线，不临时升级软件。

短期目标是可用、正确、能交付，不是两天掌握所有算法。

## 15. 十个具体练习任务

| 任务 | 操作 | 通过标准 |
|---|---|---|
| 1. 文件审计 | 扫描一个题目的全部附件与工作表 | 输出文件/字段/主键/单位/缺失清单 |
| 2. 连接检查 | 用 2023 商品信息连接销量流水 | 行数与总量守恒，无静默丢失和重复 |
| 3. 特殊值处理 | 分别处理未运输 0、退货负数、未检出 | 每种处理有题意依据与日志 |
| 4. 时间解析 | 处理日期和孕周文本 | 正确值通过，非法与歧义输入明确报出 |
| 5. 基线预测 | 均值、同期值、线性模型比较 | 划分正确，保留逐条预测明细 |
| 6. 泄漏反例 | 故意让同对象跨集合，再修复 | 能解释分数差异与有效评估方式 |
| 7. MILP 验证 | 求解两产品问题，再扩展资源限制 | 与枚举一致；不可行例子能识别 |
| 8. 不确定性 | 固定方案在相同场景下比较 | 种子、分布、依赖、指标有记录 |
| 9. 模板导出 | 填写一份指定结果模板并重新读取 | 文件名、行列、对象、单位与约束通过 |
| 10. 端到端交付 | 从原始输入生成图表与结果包 | 不手改中间数据，一条入口可复跑 |

任务 6 仅用于赛前理解错误，正式作品不能把泄漏版成绩作为有效性能。

## 16. 上场前自测清单

### 数据

- [ ] 能独立处理多工作表、复杂表头、日期、编号和百分数。
- [ ] 不依赖手工 Excel 修改完成核心清洗。
- [ ] 能检查主键、连接、缺失、异常、单位和总量。
- [ ] 知道重复记录、重复测量和重复实体不是一回事。

### 模型与验证

- [ ] 能实现可运行的回归/分类基线与 Pipeline。
- [ ] 能根据对象和时间约束设计切分，而非无条件随机划分。
- [ ] 不在测试集上学习预处理、调参或选阈值。
- [ ] 能实现小 MILP 并读取状态、间隙和可行性。
- [ ] 能对最终导出方案独立验解。
- [ ] 能固定并记录随机实验，明确情景是否含未来信息。

### 工程与交付

- [ ] 有完整入口、配置、日志、依赖和输入说明。
- [ ] 重启内核/进程后能够从原始输入重跑。
- [ ] 主要图表背后有数据表，论文数字可追溯。
- [ ] 指定 Excel 模板经过导出后重读验证。
- [ ] 保留经验证的基线和最终版本，可回滚。
- [ ] 已实际演练匿名、源码附录、AI 记录和材料打包。
- [ ] 没有把个人路径、密钥、Git 历史或环境目录打进提交包。

**编程手的水平，不只体现在“能跑多复杂的模型”，更体现在“能否及时发现错，并让队友放心使用结果”。**
